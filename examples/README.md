# Examples

## Purpose

Illustrative, non-normative examples of APS-compliant specification artifacts and SDK usage patterns.

## Responsibility

Support adoption by demonstrating correct usage without defining requirements or constraints.

## Expected Contents

| Artifact | Description |
|----------|-------------|
| Specification samples | Worked examples of valid specification constructs |
| Builder usage samples | Example inputs and expected builder outputs |
| Integration patterns | Reference patterns for downstream consumers |

## Relationships

| Directory | Relationship |
|-----------|--------------|
| [`aps/`](../aps/) | Authoritative source — examples must not override normative rules |
| [`templates/`](../templates/) | Scaffolds for creating new examples |
| [`builder/`](../builder/) | Examples serve as builder input during development and testing |
| [`tests/`](../tests/) | Examples may inform test fixtures but do not replace conformance tests |
| [`knowledge/`](../knowledge/) | Conceptual reference; examples/ provides concrete illustrations |

Examples will be populated in Phase 4 of [ROADMAP.md](../ROADMAP.md).
